# Развёртывание Floe

- Сайт: https://gru2007.github.io/floe/
- Приложение Antarctic Wallet: https://aw.me/app/29027654
- App ID: `29027654`.
- В кабинете Antarctic Wallet укажите **App URL**: `https://gru2007.github.io/floe/`.
- Манифест Antarctic: https://gru2007.github.io/floe/config.json
- Манифест TON Connect: https://gru2007.github.io/floe/tonconnect-manifest.json

Секрет Antarctic не нужен этой статической версии: она использует SDK для интерфейса кошелька, а TON Connect — для подписания транзакций. Не добавляйте `awsec_…` в исходники, config.json или GitHub Pages.

## Скрытые настройки

Нажмите на логотип Floe 7 раз подряд на главной странице или на странице «Инфо». Прямая ссылка: https://gru2007.github.io/floe/#/settings

Здесь выбирается testnet/mainnet, задаются отдельные списки всех фабрик и активная фабрика для создания. Старые адреса оставляйте в общем списке: это сохраняет каталог, баланс, графики и торговлю старыми токенами. Пустая активная фабрика отключает создание новых токенов. Выбор сохраняется только в браузере или WebView, где его сделали. При сохранении TON-кошелёк отключается; подключите его заново в нужной сети. Приложение проверяет сеть кошелька перед отправкой и явно указывает её в транзакции.

Это скрытый экран, а не авторизация администратора: его может открыть любой, но изменения действуют только у него. Секретов и приватных ключей на экране нет.

Кнопка «Вернуть настройки сайта» удаляет локальное переопределение сети и фабрик.

## Какие контракты развернуть

Нужна **одна фабрика Factory в каждой используемой сети**. Для testnet и mainnet требуются отдельные развёртывания.

`deployFactory` компилирует Factory, Token и JettonWallet. Код Token и JettonWallet сохраняется внутри фабрики. Отдельно развёртывать их вручную не нужно: фабрика создаёт Token при запуске нового токена, а JettonWallet создаётся для держателя автоматически.

## Команды

Требуется Node.js 22. В каталоге клонированного репозитория:

```bash
npm ci
npm test -- --runInBand
npm run build
```

Сначала запустите фабрику в тестовой сети:

```bash
npx blueprint run deployFactory --testnet --tonconnect
```

Подключите свой TON-кошелёк через показанную ссылку/QR и подпишите транзакцию. В testnet нужны тестовые TON. Скрипт отправляет на фабрику **0.3 TON**, плюс комиссия кошелька/сети. Адрес владельца фабрики — адрес подписавшего кошелька; ему доступны управление комиссиями и вывод дохода платформы.

После подтверждения скрипт выведет `Factory: ...`. Вставьте этот адрес в список **«Фабрики testnet»** и поле **«Активная фабрика testnet»** в скрытых настройках, сохраните и проверьте создание, покупку и продажу токена.

Когда будете готовы к основной сети, выполните отдельное развёртывание:

```bash
npx blueprint run deployFactory --mainnet --tonconnect
```

В mainnet нужны настоящие TON. Выведенный адрес относится к mainnet — поместите его в соответствующее поле. Контракты не проходили внешний аудит.

По умолчанию плата за создание токена — **0.3 TON**, комиссия платформы — **1%**. Эти параметры можно явно задать перед запуском:

```bash
DEPLOY_FEE=0.3 PLATFORM_FEE_BPS=100 npx blueprint run deployFactory --testnet --tonconnect
```

## Подключить фабрики для всех пользователей

Скрытые настройки предназначены для локальной проверки. Чтобы фабрика подключилась у всех пользователей, измените `app/public/floe.config.json` в GitHub:

```json
{
  "network": "testnet",
  "networks": {
    "testnet": { "factories": ["АДРЕС_ТЕСТОВОЙ_ФАБРИКИ"], "activeFactory": "АДРЕС_ТЕСТОВОЙ_ФАБРИКИ" },
    "mainnet": { "factories": ["АДРЕС_ОСНОВНОЙ_ФАБРИКИ"], "activeFactory": "АДРЕС_ОСНОВНОЙ_ФАБРИКИ" }
  }
}
```

Пример показывает только нужные поля: сохраните остальные настройки файла. Поле `network` задаёт сеть по умолчанию. Для разных сетей также можно задать свои `toncenterUrl` и `toncenterApiKey` внутри `networks.testnet`/`networks.mainnet`. Любой ключ в статической конфигурации будет публичным.

Закоммитьте изменение в `main`. GitHub Actions проверит контракты, соберёт сайт и опубликует обновление. Если вы ранее сохраняли локальные адреса, нажмите «Вернуть настройки сайта», чтобы перейти на общую конфигурацию.

Пока фабрики не развёрнуты, сайт работает, но создание токенов и торговля ими недоступны.

## Миграция фабрики

1. Разверните новую Factory с исправленным Token в той же сети. Прежние токены остаются на своих адресах; переносить их балансы и резервы не нужно.
2. Для фабрик этой версии владелец может **необратимо** запретить создание новых токенов в прежней фабрике, указав её преемника:

```bash
npx blueprint run retireFactory СТАРАЯ_ФАБРИКА НОВАЯ_ФАБРИКА --testnet --tonconnect
```

Для основной сети замените `--testnet` на `--mainnet`. Скрипт проверяет, что новая фабрика развёрнута, активна, поддерживает миграцию и принадлежит тому же владельцу. Подпись в кошельке нужна только для транзакции закрытия. На неё прикладывается 0.05 TON, остаток возвращается. Повторно активировать закрытую фабрику или заменить её преемника нельзя. Настройки комиссий и вывод платформенных комиссий остаются доступны владельцу, старые токены продолжают работать.

3. В общей конфигурации сайта оставьте обе фабрики в `factories` и укажите только новую в `activeFactory`:

```json
{
  "factories": ["СТАРАЯ_ФАБРИКА", "НОВАЯ_ФАБРИКА"],
  "activeFactory": "НОВАЯ_ФАБРИКА"
}
```

Этот объект относится к `networks.testnet` или `networks.mainnet`. Значение `activeFactory: null` приостанавливает создание, сохраняя старые токены. Если поле отсутствует в старом конфиге, выбирается последний **указанный** адрес. Когда активная фабрика недоступна или закрыта, интерфейс не переключается на старую фабрику автоматически. Статус активной фабрики перечитывается перед созданием.

**Фабрики v1, развёрнутые до появления `retireFactory`, нельзя закрыть on-chain:** их код неизменяемый и не содержит этого метода. Скрипт обнаруживает такую фабрику и не отправляет транзакцию. Для v1 переключение `activeFactory` запрещает создание через интерфейс Floe, но прямой вызов старого контракта из другого клиента останется возможным. Все новые фабрики поддерживают необратимое закрытие на уровне контракта.

## Уведомления о минте

Изменение с 1 nanoTON исправляло отсутствие сообщения, но такой платёж вызывает `cskip_no_gas` на Wallet V4/V5 и может отображаться как ошибочное получение TON. Текущая версия пересылает 0.01 TON с `transfer_notification`. Сумма берётся из прежних 0.05 TON на газ и возвращается покупателю, а не добавляется к резерву кривой или комиссии. Проверены первая, повторная и минимальная покупки, а также первая покупка автора на реальном коде Wallet V4 и V5 в sandbox.

Исправление применяется к новым Token, создаваемым новой фабрикой. Уже развёрнутые токены и прошлые транзакции оно не переписывает. Проверку отображения новой версии в живом кошельке нужно выполнить после отдельного развёртывания в testnet.
