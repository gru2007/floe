# Развёртывание Floe

- Сайт: https://gru2007.github.io/floe/
- Приложение Antarctic Wallet: https://aw.me/app/29027654
- App ID: `29027654`.
- В кабинете Antarctic Wallet укажите **App URL**: `https://gru2007.github.io/floe/`.
- Манифест Antarctic: https://gru2007.github.io/floe/config.json
- Манифест TON Connect: https://gru2007.github.io/floe/tonconnect-manifest.json

Секрет Antarctic не нужен этой статической версии: она использует SDK для интерфейса кошелька, а TON Connect — для подписания транзакций. Не добавляйте `awsec_…` в исходники, config.json или GitHub Pages.

## Скрытые настройки

Нажмите на логотип Floe 7 раз подряд на главной странице или на странице «Инфо». Прямая ссылка: https://gru2007.github.io/floe/#/settings

Здесь выбирается testnet/mainnet и задаются отдельные списки фабрик. Выбор сохраняется только в браузере или WebView, где его сделали. При сохранении TON-кошелёк отключается; подключите его заново в нужной сети. Приложение проверяет сеть кошелька перед отправкой и явно указывает её в транзакции.

Это скрытый экран, а не авторизация администратора: его может открыть любой, но изменения действуют только у него. Секретов и приватных ключей на экране нет.

Кнопка «Вернуть настройки сайта» удаляет локальное переопределение сети и фабрик.

## Какие контракты развернуть

Нужна **одна фабрика Factory в каждой используемой сети**. Для testnet и mainnet требуются отдельные развёртывания.

`deployFactory` компилирует Factory, Token и JettonWallet. Код Token и JettonWallet сохраняется внутри фабрики. Отдельно развёртывать их вручную не нужно: фабрика создаёт Token при запуске нового токена, а JettonWallet создаётся для держателя автоматически.

## Команды

Требуется Node.js 22. В каталоге клонированного репозитория:

```bash
npm ci
npm test -- --runInBand
npm run build
```

Сначала запустите фабрику в тестовой сети:

```bash
npx blueprint run deployFactory --testnet --tonconnect
```

Подключите свой TON-кошелёк через показанную ссылку/QR и подпишите транзакцию. В testnet нужны тестовые TON. Скрипт отправляет на фабрику **0.3 TON**, плюс комиссия кошелька/сети. Адрес владельца фабрики — адрес подписавшего кошелька; ему доступны управление комиссиями и вывод дохода платформы.

После подтверждения скрипт выведет `Factory: ...`. Вставьте этот адрес в поле **«Фабрики testnet»** в скрытых настройках, сохраните и проверьте создание, покупку и продажу токена.

Когда будете готовы к основной сети, выполните отдельное развёртывание:

```bash
npx blueprint run deployFactory --mainnet --tonconnect
```

В mainnet нужны настоящие TON. Выведенный адрес относится к mainnet — поместите его в соответствующее поле. Контракты не проходили внешний аудит.

По умолчанию плата за создание токена — **0.3 TON**, комиссия платформы — **1%**. Эти параметры можно явно задать перед запуском:

```bash
DEPLOY_FEE=0.3 PLATFORM_FEE_BPS=100 npx blueprint run deployFactory --testnet --tonconnect
```

## Подключить фабрики для всех пользователей

Скрытые настройки предназначены для локальной проверки. Чтобы фабрика подключилась у всех пользователей, измените `app/public/floe.config.json` в GitHub:

```json
{
  "network": "testnet",
  "networks": {
    "testnet": { "factories": ["АДРЕС_ТЕСТОВОЙ_ФАБРИКИ"] },
    "mainnet": { "factories": ["АДРЕС_ОСНОВНОЙ_ФАБРИКИ"] }
  }
}
```

Пример показывает только нужные поля: сохраните остальные настройки файла. Поле `network` задаёт сеть по умолчанию. Для разных сетей также можно задать свои `toncenterUrl` и `toncenterApiKey` внутри `networks.testnet`/`networks.mainnet`. Любой ключ в статической конфигурации будет публичным.

Закоммитьте изменение в `main`. GitHub Actions проверит контракты, соберёт сайт и опубликует обновление. Если вы ранее сохраняли локальные адреса, нажмите «Вернуть настройки сайта», чтобы перейти на общую конфигурацию.
